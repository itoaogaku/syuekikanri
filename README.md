# 売上レポート自動化（Wix × Stripe × Komoju）

Wix の決済（Stripe / Komoju）について、**月次の入金内訳を自動で集計し、Google スプレッドシートに報告レポートを作成する** Google Apps Script（GAS）です。

毎月の「入金があった → 何がいくら売れたか整理して報告」という作業を自動化します。
データは**年間で蓄積**され、**年度ごと・事業ごと**に合計が出ます。

## できること

月次でデータを取得すると **台帳（明細DB）に蓄積**され、そこから次のレポートを自動生成します。

| シート | 内容 |
|---|---|
| **年度サマリー** | 年度ごとの **Stripe / Komoju それぞれの年間合計**（総売上・返金・手数料・純額）と月別推移 |
| **事業別サマリー** | 年度ごと・**事業ごとの入金額**（Stripe入金／Komoju入金／合計） |
| **商品別売上** | 年度ごとの商品／注文別 |
| **決済手段別** | 年度ごとの カード／コンビニ／銀行振込／PayPay 等 |
| **入金照合** | 各入金（振込）について「明細の純額合計＝実際の入金額」かを検算 |
| **明細DB / 入金DB** | 蓄積される元データ（年間を通して追記されていく） |

- **蓄積型**：毎月実行するたびに台帳へ追記されます。同じ月を再実行しても重複しません（その月分だけ入れ替え。遅れて発生した返金も反映されます）。
- **年度**：会計年度に対応。既定は **4月始まり（4月〜翌3月）**。開始月は設定で変更でき、`1` にすると暦年になります。
- **事業**：「事業マッピング」シートで、キーワード→事業名 を定義して振り分けます。
- **Stripe**：入金（payout）ごとに含まれる取引を自動でひも付け。売上・手数料・返金・実際の入金額まで正確に照合します。
- **Komoju**：期間内の決済を取得し、決済手段別・商品別・事業別に集計します。

## セットアップ

### 1. スプレッドシートに導入する（コピペ or clasp）

**簡単な方法（コピペ）**
1. Google スプレッドシートを新規作成
2. メニュー「拡張機能 > Apps Script」を開く
3. `src/` 内の各 `.gs` ファイルの中身を、同名のファイルを作ってそれぞれ貼り付け
4. `appsscript.json` の内容も反映（プロジェクトの設定 > 「appsscript.json マニフェスト ファイルを表示」をON）
5. 保存してスプレッドシートを再読み込み

**開発者向け（clasp）**
```bash
npm i -g @google/clasp
clasp login
clasp create --type sheets --title "売上レポート"   # または既存の scriptId を .clasp.json に設定
clasp push
```

### 2. APIキー・年度開始月を設定

スプレッドシートのメニュー **「売上レポート > ① APIキー・年度開始月を設定」** から入力します。

- **Stripe**：シークレットキー（`sk_...`）。安全のため **読み取り専用の制限キー（Restricted key）** の発行を推奨。
  - 必要な権限：`Payouts` 読み取り、`Balance transactions` 読み取り、`Charges` 読み取り
- **Komoju**：シークレットキー
- **Komoju 手数料率**：純額の概算に使用（例 `3.65%` なら `0.0365`）
- **年度の開始月**：`4`（4月始まり）が既定。暦年で集計したい場合は `1`。

> キーはコードに書かず、GAS の「スクリプトプロパティ」に安全に保管されます。

### 3. 事業マッピングを設定

メニュー **「② 事業マッピングを編集」** で「事業マッピング」シートを開き、
**キーワード → 事業名** の対応を入力します（商品名・注文IDにキーワードが含まれる取引を、その事業へ分類）。

| キーワード | 事業名 |
|---|---|
| 講座 | オンライン講座事業 |
| 書籍 | 出版事業 |
| グッズ | 物販事業 |

編集後は **「⑤ レポートを再作成」** で反映されます（データ再取得は不要）。

### 4. データを取得・蓄積

- **「③ 先月分を取得して反映」**：前月分を取得して台帳に追記
- **「④ 月を指定して取得」**：`2026-06` のように指定（過去分をまとめて入れるときに使用）
- **「⑤ レポートを再作成」**：取得済みの台帳から集計だけ作り直す（事業マッピング変更後など）
- **「⑥ 毎月の自動取得をON」**：毎月5日9時台に前月分を自動取得・蓄積

まずは **「★ サンプルデータで表示を確認」** で、APIキーなしでも 2年度・複数事業のレポートの見た目を確認できます。

## ファイル構成

| ファイル | 役割 |
|---|---|
| `src/Main.gs` | メニュー・月次取得・レポート再生成・トリガー・設定 |
| `src/Config.gs` | 設定値・キー管理 |
| `src/Business.gs` | 年度の計算・事業への振り分け |
| `src/Ledger.gs` | 台帳への蓄積（明細DB／入金DB）と読み出し |
| `src/Stripe.gs` | Stripe API（入金と取引のひも付け） |
| `src/Komoju.gs` | Komoju API（決済取得） |
| `src/Aggregate.gs` | 年度・事業・決済別の集計ロジック |
| `src/Report.gs` | スプレッドシートへの書き出し |
| `src/Http.gs` | HTTP 共通処理 |
| `src/Sample.gs` | サンプルデータ |

## 実データに合わせた調整ポイント

コードは一般的な形で作っていますが、御社の実際のデータに合わせて **1回だけ調整が必要** な箇所があります。

1. **商品名の取得元**（`Stripe.gs` の `stripeProductLabel_`）
   Wix が Stripe/Komoju に何を渡しているかで、商品名の入る場所が変わります（`description` か `metadata` か）。実データ1件を見て合わせます。
   - より正確な「商品名・数量」が必要な場合は、**Wix 注文API との突合**を第2段階で追加できます（注文ID `orderId` でひも付け）。

2. **Komoju の手数料・入金単位**（`Komoju.gs`）
   Komoju の手数料は payment API から常に取れるとは限らないため、現状は **設定した手数料率による概算** です。正確な手数料・入金額は Komoju の精算レポートで確定するため、必要ならその取り込みを追加します。

3. **事業の振り分けキーワード**（「事業マッピング」シート）
   商品名がどう入るかに合わせて、キーワードを調整してください。うまく分類されない取引は「未分類」に集計されるので、そこを見てキーワードを追加すれば精度が上がります。

## 注意事項

- データは「明細DB」「入金DB」シートに蓄積されます。**これらのシートは手で編集・削除しないでください**（集計の元データです）。
- 通貨は日本円（JPY）前提です。他通貨を扱う場合は `Config.gs` の `CURRENCY` を調整してください。
- APIキーは絶対にこのリポジトリにコミットしないでください（スクリプトプロパティで管理します）。
